## Read first: why the triad kernel forces fractal weights

The most important correction to this source map is that the project does **not** merely move away from scalar counts because scalar counts were weak. It moves away from scalar counts because the **RFC triad kernel** forces every arithmetic state to preserve recursive memory. In the twin-prime translation, that recursive memory becomes **fractal / inherited / branch-weighted structure**.

The compact relationship is:

```text
Triad kernel
  -> CIF/QV/RFL handoff
  -> scalar counts are insufficient
  -> inherited/fractal-weight packets are required
```

Equivalently:

```text
Fractal weights are the arithmetic expression of the triad kernel.
```

This is the reason the route repeatedly refuses to treat a proof object as only a number. Each scalar object must be reopened into the three triad components plus the handoff rule:
