# Source Soak Protocol

A source soak is complete only when it produces repository memory, not merely a chat impression.

## Order

1. Verify bundle and seed hashes.
2. Read Presentation 29 revised and metadata.
3. Read the revised N-body proof and metadata, including figures/equations.
4. Read Presentation 30 and reproducibility metadata.
5. Read the triad/kernel source book and story arc for terminology and intuition.
6. Read P24-P28 and historical ledgers only to recover valid objects, failures, and evolution of the architecture.
7. Inspect the old 2-RFC repository and candidate run bundles by exact commit/file/hash.

## Required source card

For every material source create a record containing:

- exact path/hash/version;
- authority class;
- definitions and terminology;
- theorem/law objects;
- physical objects;
- numerical objects;
- claim boundaries;
- failures/limitations;
- target modules;
- preserve/strengthen/rederive/execute/reserve/quarantine disposition.

## PDF rule

Render and inspect PDF pages when figures, tables, equation layout, or diagrams matter. Parsed text alone is not sufficient for visual evidence.

## Stop rule

Do not proceed from a remembered source. If exact bytes cannot be recovered, mark the object blocked or use a lawful fresh derivation that does not pretend to be the missing source.
